# CodinginX — Official Production Website

You are responsible for designing, engineering, testing, securing, validating, and delivering the **official production website for CodinginX**.

This is NOT:

- a temporary landing page
- a mockup
- a quick startup template
- a throwaway MVP website
- a generic AI-generated agency site
- a "vibe-coded" website
- a website we intend to rebuild immediately after launch

Treat this as the **long-term foundation of CodinginX's public web presence**.

The architecture, design system, content structure, SEO, components, project data, contact workflow, security, monitoring, and code quality should be built so the website can evolve for years as the company gains clients, projects, team members, case studies, articles, services, and new capabilities.

Make reasonable professional decisions yourself.

Do not repeatedly stop to ask minor questions.

Do not sacrifice engineering quality for visual novelty or speed.

The finished website should be something CodinginX can confidently connect to its real domain and use publicly as its official company website.

# 23. MOTION

Animation should be restrained and purposeful.

Use animation only where it improves:

- orientation
- comprehension
- feedback
- navigation
- transitions
- product demonstrations
- workflow explanations
- perceived polish

Good examples:

- restrained entrance animation
- subtle fade/translation
- navigation transition
- smooth mobile menu
- product preview movement
- interface state transition
- animated workflow diagram
- button feedback
- loading transition
- chatbot opening/closing

Visitors should notice the **quality**, not the animation itself.

---

# 24. FORBIDDEN MOTION

Do NOT use:

- exaggerated scroll animations
- elements flying across the screen
- excessive parallax
- constant background movement
- cursor-following effects
- custom animated cursors
- cursor trails
- animated arrows
- floating blobs
- moving glow orbs
- particle systems
- rotating decorative objects
- bouncing elements
- excessive card movement
- card tilt
- dramatic hover lift
- unnecessary glow
- constant loops
- excessive text reveals
- huge scroll transformations
- animation that delays content

Do not try to make the site look futuristic through animation.

---

# 25. HOVER BEHAVIOR

Hover should primarily communicate interactivity.

Good:

- color change
- border change
- underline
- background-tone change
- subtle opacity change
- restrained icon movement

Avoid:

- dramatic scaling
- rotation
- tilt
- glow
- bouncing
- giant shadows
- large translation

Interactive elements should feel responsive, not playful.

---

# 26. SCROLL BEHAVIOR

Keep browser scrolling natural.

Do NOT hijack scrolling.

Avoid:

- unnecessary scroll snapping
- excessive pinned sections
- artificial scroll speed
- horizontal scroll for normal content
- large blank animation spaces
- aggressive motion opposite the scroll direction

If scroll-triggered animation is used:

- keep it subtle
- trigger once where practical
- keep content readable immediately
- prevent layout shift
- never require animation to finish before users can understand content

---

# 27. PAGE TRANSITIONS

Page transitions are optional.

If used:

- keep them fast
- keep them subtle
- do not delay navigation
- preserve perceived performance

Fast navigation matters more than decorative transitions.

---

# 28. PRODUCT DEMONSTRATION MOTION

More expressive motion is acceptable inside **real product demonstrations** where it illustrates functionality.

Examples:

- lead entering automation
- email converted into structured information
- scheduling status changing
- dashboard updating
- chatbot conversation
- workflow nodes processing information
- API/system connections

This animation should explain the product rather than decorate the site.

---

# 29. MOTION PERFORMANCE

Animation must not materially harm:

- LCP
- INP
- CLS
- mobile performance
- accessibility
- battery usage

Avoid unnecessarily large animation dependencies.

Do not convert server-renderable components to client components solely to animate them.

Respect:

`prefers-reduced-motion`

When reduced motion is requested:

- remove nonessential movement
- disable parallax
- eliminate decorative movement
- remove large entrance effects
- preserve meaningful state changes
